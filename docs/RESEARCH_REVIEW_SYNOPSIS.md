Determining the asymptotic computational complexity of software, specifically its worst-case time complexity expressed in Big-O notation, is an essential problem in algorithm design, software optimization, and computer science education. Accurately determining algorithmic scaling enables developers to identify performance bottlenecks early and helps prevent algorithmic complexity vulnerabilities such as denial-of-service induced by pathological inputs. However, automated complexity analysis for imperative languages like C++ is fundamentally constrained by Rice's Theorem and the undecidability of the Halting Problem, which establish that no general algorithm can statically decide termination or exact operational step counts for arbitrary Turing-complete code.

In practice, static program analyzers rely on abstract interpretation, symbolic execution, or recurrence relations. While these formal methods provide mathematical soundness for restricted code patterns, they frequently fail or abstain when encountering complex standard library abstractions, pointers, dynamic dispatch, or real-world idioms. Recent research has also explored deep learning and large language models for complexity prediction, such as the CodeComplex benchmark by Baik et al. (https://doi.org/10.18653/v1/2025.findings-emnlp.1069) and the TCProF semi-supervised learning framework by Hahn et al. (https://doi.org/10.18653/v1/2025.naacl-long.482). Although machine learning can identify statistical heuristics in complex code, pure predictive models lack correctness guarantees, hallucinate on unfamiliar control flow, cannot verify mathematical upper bounds, and produce unexplainable outputs without causal derivations. Similarly, while contrastive representation learning by Park et al. (https://doi.org/10.1016/j.engappai.2025.110631) clusters semantic representations by complexity, and exact loop bound analysis by Riley and Fedyukovich (https://doi.org/10.1145/3729323) offers formal precondition synthesis, existing tools remain polarized between fragile formal provers and unverified black-box classifiers.

ComplexityLens addresses this dichotomy by developing an explainable hybrid analysis system for standalone C++ programs. Rather than relying solely on static rules or machine learning, the architecture pairs lightweight deterministic static analysis with calibrated machine learning, mediated by a deterministic verification and abstention gate. The analysis begins with an input validation layer that enforces file length, line width, brace-nesting limits, and a strict include directive allowlist covering standard containers such as vector, algorithm, cmath, set, and map. This pre-parser safety layer prevents preprocessor injection and unsupported system dependencies before the code is translated via libclang into a typed, parser-independent Intermediate Representation that captures function scopes, nested loop bounds, call expressions, container operations, and recursion call-sites.

The static analysis engine evaluates complexity without heavy, unscalable theorem provers by modeling asymptotic complexity as polynomial-logarithmic degree pairs, denoted as (p, q), representing terms of the form n to the power p multiplied by log n to the power q. The engine analyzes loop step conditions to classify constant, linear, doubling, halving, and triangular iterations. Loop nesting is evaluated through degree addition, while sequential code blocks are combined using algebraic dominance. The static engine incorporates verified cost models for standard algorithms and containers, such as sorting, linear searching, binary searching, and amortized container mutations. To evaluate multi-function programs, non-recursive helper calls are substituted across call graphs using Tarjan's strongly connected components algorithm, and standard divide-and-conquer recurrences are resolved using conservative recurrence templates.

For programs where syntactic rules are brittle, ComplexityLens extracts a twenty-six-dimensional structural feature vector directly from the Intermediate Representation. These features capture loop nesting depth, loop counts, linear and logarithmic update styles, recursion branching factors, argument reduction modes, call-site frequencies, container operations, and unsupported construct counts. Features are derived strictly from AST topology and syntax without data leakage from static engine outcomes. These numerical representations serve as input to calibrated supervised classifiers, such as XGBoost and Random Forest, which predict class probabilities across the supported complexity taxonomy.

The core safety barrier in ComplexityLens is its deterministic verification and abstention gate. When static analysis proves an exact complexity class and the machine learning model agrees, the prediction is accepted with high confidence. When static analysis establishes a proven upper bound, any machine learning prediction that exceeds this upper bound is strictly rejected. Furthermore, whenever a severe contradiction arises, or whenever the Intermediate Representation detects fundamentally unmodeled code, the gate refuses to guess and emits an explicit UNKNOWN outcome. This abstention is accompanied by structured reason codes that specify whether the code exhibits runtime data-dependent bounds, uncertain termination such as floating-point precision limits, unsupported language constructs like lambdas with internal loops or function pointers, opaque external calls, or irregular recursion. Finally, rather than emitting an unexplained classification, ComplexityLens produces an evidence-based explanation that cites exact line numbers, AST node spans, and dominant computational paths.

The project is currently scoped to standalone single-translation-unit C++ source files of up to two hundred lines, focusing strictly on worst-case time complexity across constant, logarithmic, linear, linearithmic, quadratic, cubic, and exponential classes. Space complexity analysis is identified as future work. The primary project objectives are to implement a safe parsing and intermediate representation pipeline, formulate a deterministic static complexity algebra with line-level evidence tracking, design a leakage-free structural feature extractor, curate an author-verified benchmark dataset across diverse complexity classes including rule-hard samples, train calibrated classifiers, and construct a deterministic verification gate that eliminates hallucinations through principled abstention. The input validation layer, libclang intermediate representation builder, static polynomial engine, feature extractor, benchmark dataset, and command-line interface are fully implemented and verified, while machine learning model calibration and gate fusion represent the planned next stages of the system.
